# 施工图审查（drawing-review）

把“拖进图纸 → 自动解析 → 按清单审查 → 结果可回原图 → 人工确认”的审图流程交给你执行。产出是**给设计人员核对的候选问题清单**，不是正式审图意见，也不是合规结论。

## 不可违反的规则

1. **图签与身份信息不审查、不外传。** 图签（设计/校对/审核/审定等签署栏、设计单位、建设单位、工程名称、日期、出图章、注册章、证书编号、电话）是脱敏数据，不属于审查范围。不要报告“签字不全”“单位名称写法”“图签日期”之类问题。
2. **不要直接打开原始图纸。** 只读取 `extract` 生成的 `review_input.md` / `blocks.jsonl`（已剔除图签、已脱敏）。`mapping.local.json` 含原文对照，**永远不要读取、引用或上传**。报告中保留占位符（如［单位1］），不要尝试还原。
3. **只报能用图纸原文证明的问题。** 每条问题至少一段逐字引文 + 块编号（如 `P3-b12`）。不能从给定文字证明的不报；OCR 噪声、版式顺序造成的“相邻文字”不当作同一构件。
4. **规范结论必须有可核对的依据。** 不凭记忆断言“规范要求应为某值”、不编造条文号。只有 `references/verified-rules.md` 里的已核对规则可以给出“低于规范”类结论；其他涉及规范的只能写“相关条文待核对”或 `needs_context`。规范是否现行要联网到官方来源核实，查不到就写“未核实”，不能当作现行或废止。
5. **缺前提就不下结论。** 缺构件类别、设计工作年限、抗震等级、环境类别、适用范围等前提时，结论是 `needs_context`（需补充条件），不是疑似问题。
6. **宁缺毋滥。** 价值在于少而准；同一问题多处出现合并为一条，列出全部位置。“未发现问题”只表示在本次检查项和可读文字范围内未命中，**不得写“审查合格/符合规范”**。

## 流程

### 第 0 步：确认范围（一句话即可，不要让用户填表）

- 用户给了审查重点（如“只看防水”“重点查梁配筋”“结构总说明”）就按重点；没给就按 `references/review-checklist.md` 全部检查项。
- 专业不明确时不猜，标“专业未知”，只做通用检查项。
- 若工程所在地区影响地方标准适用，请用户直接说省份；工程名称已脱敏，不要从占位符推断。

### 第 1 步：本机抽取与脱敏

```bash
pip install pdfplumber              # 首次使用；国内可加 -i https://pypi.tuna.tsinghua.edu.cn/simple
python scripts/drawing_review.py extract <图纸1.pdf> [图纸2.pdf ...] --out review_pack [--extra-terms 敏感词.txt]
```

- **只支持 PDF**（需带文字层，CAD 直接导出的矢量 PDF 最好）。用户给的是 DWG/DXF 时，请他从 CAD 导出 PDF 再审查。扫描页、纯图形页、字体无法解码的页会标为“未审查”，**不要自己 OCR 或猜内容**。
- `--extra-terms`：用户额外指定的敏感词（工程简称、地名、人名），每行一个。
- 脚本输出摘要后，先告诉用户：共几页、几页未审查、剔除了多少图签文字、替换了多少敏感信息。

### 第 2 步：阅读审查材料并按清单审查

读 `review_pack/review_input.md`（太长时按页分段读）和 `references/review-checklist.md`，必要时读 `references/verified-rules.md`。

- 逐项过清单，每一批页面通常 0–2 条真正有把握的问题。
- 同时抽取关键设计参数（部位 + 参数 + 取值 + 引文），用于第二遍做**跨页**参数比对：只有“同一对象、同一参数、取值确实不同”才算矛盾；不同部位、构件、工况取值不同是正常的。
- 每条候选写成 `references/report-format.md` 规定的 JSON 结构，保存为 `review_pack/findings.json`。

### 第 3 步：自我反驳复核（必做）

对每条候选扮演严格的复核人尝试推翻它：是否 OCR 噪声？是否不同部位/工况本来就不同？是否行业惯常写法？是否依赖外部知识才成立？两处是否能确认是同一对象？**不确定一律删除或降为 `needs_context`**。在 JSON 里写明 `basis`（判断依据）。

### 第 4 步：核验引文并生成报告

```bash
python scripts/drawing_review.py verify --pack review_pack --findings review_pack/findings.json
python scripts/drawing_review.py report --pack review_pack --title "XX 审查报告（AI 辅助自查）"
```

- `verify` 会逐字核对引文（忽略空白与全半角），找不到原文的问题自动降为“待查线索”，只涉及脱敏数据的候选判为范围外，重复候选合并。
- 若降为线索的较多，回到第 2 步检查引文是否抄错，修正后重跑；**不要为了通过核验改写或编造引文**。
- `report` 生成 `review_pack/审查报告.md`。需要 Word/PDF 时在此基础上转换，不要增删结论。

### 第 5 步：向用户汇报

用 3–6 行说明：疑似问题几条（列最重要的 1–3 条标题和位置）、需补充条件几条、哪些页/内容未审查、报告文件路径。提醒报告中的问题须逐条人工确认。用户确认或排除某条后，在后续复查中**沿用用户的决定**，不要被重新审查覆盖。

## 复查（修改后再审）

用户提供新版图纸时：重新 `extract` 到新目录，审查后与上一版 `verified.json` 对照。上一版有、本版没有的写“本次未再出现”（可能已修改，也可能因识别差异未检出），**不说“已修复”**；上一版用户已排除的同一问题保持排除。

## 参考文件

- `references/review-checklist.md`：审查检查项（C1–C9）、各专业关注点、不要报告的内容。
- `references/verified-rules.md`：已核对可执行的规范规则（混凝土最低强度等级等）与已核实的标准替代关系。
- `references/desensitization.md`：脱敏范围、占位符含义、脚本识别图签的方法与局限。
- `references/report-format.md`：`findings.json` 字段、结论分级、报告结构。
