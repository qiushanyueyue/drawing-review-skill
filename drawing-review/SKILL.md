# 施工图审查（drawing-review）

把“拖进图纸 → 自动解析 → 按清单审查 → 结果可回原图 → 人工确认”的审图流程交给你执行。产出是**给设计人员核对的候选问题清单**，不是正式审图意见，也不是合规结论。

## 不可违反的规则

1. **图签与身份信息不审查、不外传。** 图签（设计/校对/审核/审定等签署栏、设计单位、建设单位、工程名称、日期、出图章、注册章、证书编号、电话）是脱敏数据，不属于审查范围。不要报告“签字不全”“单位名称写法”“图签日期”之类问题。
2. **不要直接打开原始图纸。** 只读取 `extract` 生成的 `review_input.md` / `blocks.jsonl` / `coverage.json`，图像模式下只看 `images.json` 里列出的、已在本机遮盖过的图片。`mapping.local.json` 含原文对照，**永远不要读取、引用或上传**。报告中保留占位符（如［单位1］），不要尝试还原。
3. **只报能用图纸原文证明的问题。** 每条问题至少一段逐字引文 + 块编号（如 `F1-P3-B12`）。不能从给定文字证明的不报；PDF 抽取顺序造成的“相邻文字”不当作同一构件。
4. **对象对应要能证明。** 两处文字比较前，先确认是同一构件/断面/部位/工况（同一编号且楼层区域明确、明确的详图索引、同一条款上下文）。跨页、跨文件比较必须写 `object_match: "explicit"` 并在 `basis` 说明依据；只是推断的写 `inferred`，脚本会降为“需补充条件”。
5. **规范结论必须有可核对的依据。** 不凭记忆断言“规范要求应为某值”、不编造条文号。只有 `references/verified-rules.md` 里的已核对规则可以给出“低于规范”类结论；其他涉及规范的只能写“相关条文待核对”或 `needs_context`。规范是否现行要联网到官方来源核实，查不到就写“未核实”。
6. **数值让脚本算。** 复核计算书算式、钢筋面积、配筋率时用 `calc` 命令或在 findings 里写 `calculation`，不要心算；缺参数就写 `needs_context`，**不得自行补全参数**。
7. **图像识读只作辅助。** 看图读到的尺寸、配筋若在文字层里找不到佐证，只能是“需补充条件”，注明须回原图核实；不要虚构看不清的直径、间距、根数。
8. **宁缺毋滥。** 价值在于少而准；同一问题多处出现合并为一条，列出全部位置。“未发现问题”只表示在本次检查项和可读范围内未命中，**不得写“审查合格/符合规范”**。

## 流程

### 第 0 步：确认范围与模式（一两句话即可，不要让用户填表）

- 用户给了审查重点（如“只看防水”“重点查梁配筋”“某断面与计算书是否对应”）就按重点；没给就按 `references/review-checklist.md` 全部检查项。
- 专业不明确时不猜，标“专业未知”，只做通用检查项。地方标准适用地区请用户直接说省份；工程名称已脱敏，不要从占位符推断。
- **选择模式**：
  - **文字模式**（默认，任何模型都能用）：只读文字层，用块坐标和 `near` 判断标注归属。
  - **图像模式**（可选）：仅当你确实能查看图片，**并且**用户明确同意把本机遮盖后的页面图交给当前模型时使用。第 1 步结束后若有“以图形为主”的页或用户要查配筋/尺寸，可以用一句话问：“这些页以图形为主，要不要把遮盖了图签和敏感信息的页面图给我看，辅助判断标注归属？”。不能看图就不要问，直接用文字模式。

### 第 1 步：本机抽取与脱敏

```bash
pip install pdfplumber              # 首次使用；国内可加 -i https://pypi.tuna.tsinghua.edu.cn/simple
python scripts/drawing_review.py extract <图纸1.pdf> [计算书.pdf 勘察报告.pdf ...] --out review_pack [--extra-terms 敏感词.txt]
```

- **只支持 PDF**（需带文字层，CAD 直接导出的矢量 PDF 最好）。用户给的是 DWG/DXF 时，请他从 CAD 导出 PDF。扫描页、字体无法解码的页标为“未审查”，**不要自己 OCR 或猜内容**。
- 多个文件一起抽取，块编号自带文件序号（F1、F2…），跨文件比对不会混淆；`coverage.json` 里有每个文件的 SHA-256 和推测类型（图纸/计算书/勘察报告）。
- `--extra-terms`：用户额外指定的敏感词（工程简称、地名、人名），每行一个。
- 先告诉用户：共几页，已审查/以图形为主（只有少量文字）/未审查各几页，剔除了多少图签文字，替换了多少敏感信息；有“图签识别提示”或“疑似人名残留”时一并说明。

### 第 2 步：阅读审查材料并按清单审查

读 `review_pack/review_input.md`（太长时按页分段读）和 `references/review-checklist.md`，必要时读 `references/verified-rules.md`。

- 逐项过清单，每一批页面通常 0–2 条真正有把握的问题。
- 设计说明页：按 C1–C9 查。同时抽取关键参数（对象 + 参数 + 取值 + 引文），用于跨页、跨文件比对（C8、C12、C13）。
- 图纸页（配筋图、断面图、平面图）：短标注带 `@x,y` 坐标。判断某个标注属于哪个构件时运行
  `python scripts/drawing_review.py near --pack review_pack --block F1-P3-B12`（列出周围文字、方向、距离），或 `near --page F1-P3 --region x0,y0,x1,y1` 列出区域内文字。离得近不等于有关联，归属不明的不比较。
- 计算书：算式与结果用 `python scripts/drawing_review.py calc "表达式"` 复算（支持 `As(d,n)`、`As_s(d,s)`、`rho(As,b,h0)`、`sqrt`、`sind` 等），只报转抄、代入、运算错误（C14），不评价计算模型选择。
- **图像模式**（第 0 步已获同意时）：
  1. `python scripts/drawing_review.py render <同样的 PDF ...> --pack review_pack [--pages F1-P3,F1-P5]`，查看 `images.json` 列出的整页图（黑框是遮盖，蓝色网格数字是页面坐标）。
  2. 需要细节时 `python scripts/drawing_review.py zoom <PDF> --pack review_pack --page F1-P3 --region x0,y0,x1,y1`（坐标读网格数字），输出里会列出该区域内的文字块，便于引用。
  3. 看图用于判断标注、剖切号、索引与构件的对应关系；结论仍要引用文字块。图面证据写进 `visual_evidence`（页、区域坐标、读到的文字）。
  4. 扫描页、乱码页默认不渲染；**不要**加 `--allow-unmasked-pages`，除非用户明确同意并知道这些页只做了页面四周的保守遮盖。
- 每条候选写成 `references/report-format.md` 规定的 JSON 结构，保存为 `review_pack/findings.json`（写明 `check_method`、`object`、`object_match`，复算写 `calculation`）。

### 第 3 步：自我反驳复核（必做）

对每条候选扮演严格的复核人尝试推翻它：是否抽取顺序造成的错位？是否不同部位/工况/施工阶段本来就不同？两处能否确认是同一对象？是否行业惯常写法？是否依赖外部知识才成立？复算是否用了图纸里没有的参数？**不确定一律删除或降为 `needs_context`**。在 JSON 里写明 `basis`（判断依据）和 `uncertainties`（无法确认的条件）。

### 第 4 步：核验并生成报告

```bash
python scripts/drawing_review.py verify --pack review_pack --findings review_pack/findings.json
python scripts/drawing_review.py evidence <同样的 PDF ...> --pack review_pack     # 可选：为每条问题生成遮盖后的原图截图
python scripts/drawing_review.py report --pack review_pack --title "XX 审查报告（AI 辅助自查）"
```

- `verify` 给每条问题做证据分级：**E1** 引文是否逐字出现在所写块（或其后连续的块）；**E2** 跨页/跨文件比较是否声明并说明了对象对应；**E3** 复算是否证实数值不一致。引文只在别的页/文件找到时不算定位（`relocated_candidate`），问题降为“待查线索”；对象对应未确认、只有视觉识读的降为“需补充条件”；复算与文件一致的计算类问题降为线索。
- 降级较多时回到第 2 步检查引文、块编号和对象对应，修正后重跑；**不要为了通过核验改写或编造引文**。
- `evidence` 只在本机生成截图，红框标证据位置、黑框为遮盖；文字模式下不需要查看这些图片。
- `report` 生成 `review_pack/审查报告.md`。需要 Word/PDF 时在此基础上转换，不要增删结论。

### 第 5 步：向用户汇报

用 3–6 行说明：疑似问题几条（列最重要的 1–3 条标题和位置）、需补充条件几条、哪些页/内容未审查、是否用了图像模式、报告文件路径。提醒报告中的问题须逐条人工确认。用户确认或排除某条后，在后续复查中**沿用用户的决定**（`review_status`），不要被重新审查覆盖。

## 复查（修改后再审）

用户提供新版图纸时：重新 `extract` 到新目录（SHA-256 不同即为新版本），审查后与上一版 `verified.json` 对照。上一版有、本版没有的写“本次未再出现”（可能已修改，也可能因识别差异未检出），**不说“已修复”**；上一版用户已排除的同一问题保持排除。

## 参考文件

- `references/review-checklist.md`：审查检查项（C1–C15，含图纸几何、配筋、计算书与勘察参数对应、算式复算、施工阶段）、各专业关注点、不要报告的内容。
- `references/verified-rules.md`：已核对可执行的规范规则（混凝土最低强度等级等）与已核实的标准替代关系。
- `references/desensitization.md`：脱敏范围、占位符含义、图签识别与图像遮盖的方法与局限。
- `references/report-format.md`：`findings.json` 字段、结论分级、证据分级、报告结构。
