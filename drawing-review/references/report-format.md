# findings.json 与审查报告格式

## 结论分级

| decision | 含义 | 进入报告的位置 |
|---|---|---|
| `suspected` | 疑似问题：有逐字引文、能回原图，且经过自我反驳仍成立。**不是违规定论** | 二、疑似问题 |
| `needs_context` | 需补充条件：缺构件类别、年限、抗震等级、适用范围、版本核实等前提，未下结论 | 三、需补充条件 |
| `not_checked` | 该检查项本次未执行或该参数未与规范比对 | 五、核查范围与限制 |
| `lead` | 待查线索：由 `verify` 自动设置（引文无法回到原文） | 四、待查线索 |

severity：`high`（低于已核对规范最低要求、结构安全相关参数矛盾）/ `medium`（参数、构件、做法前后矛盾，引用废止标准）/ `low`（表达、书写、编号问题）/ `info`。

## findings.json

```json
{
  "focus": "结构设计总说明 + 防水",
  "rules_run": ["C1 说明内部参数一致性", "C3 防水做法一致性", "C5 引用版本（已联网核实 3 项，未核实 1 项）", "C6-V1 混凝土最低强度等级"],
  "findings": [
    {
      "id": "F1",
      "rule": "C1",
      "category": "说明内部参数矛盾",
      "title": "顶板抗渗等级前后不一致",
      "problem": "材料第1条顶板抗渗等级P10，第2条顶板为P8。",
      "suggestion": "核对顶板抗渗等级取值",
      "severity": "medium",
      "decision": "suspected",
      "confidence": 0.85,
      "basis": "两处均明确写“顶板”，同一说明“材料”节，非不同工况",
      "missing": [],
      "norm": null,
      "quotes": [
        {"block": "P3-b12", "text": "顶板、底板、侧墙混凝土强度等级C35，抗渗等级P10"},
        {"block": "P3-b13", "text": "顶板混凝土强度等级C40，抗渗等级P8"}
      ]
    },
    {
      "id": "F2",
      "rule": "C5",
      "category": "引用版本",
      "title": "引用已废止标准 GB 50015-2003",
      "problem": "说明引用 GB 50015-2003，已被 GB 50015-2019 替代。",
      "suggestion": "核对是否应按 GB 50015-2019 设计",
      "severity": "medium",
      "decision": "suspected",
      "confidence": 0.9,
      "basis": "替代关系见 verified-rules V2（住建部公告，核对于 2026-11-12）",
      "norm": {"code": "GB 50015-2019", "clause": "", "verified": true},
      "quotes": [{"block": "P2-b40", "text": "《建筑给水排水设计规范》GB 50015-2003"}]
    }
  ]
}
```

字段要求：
- `quotes[].text` **逐字复制**审查材料中块编号后的文字（可截取其中一段，至少 4 个字），`block` 填块编号。跨页矛盾至少两条引文。
- `title` ≤ 20 字；`problem` ≤ 80 字；`suggestion` ≤ 40 字，只说应核对什么，不替设计人员下结论。
- `confidence` 0–1；低于 0.7 的一般不要写入，除非是 `needs_context`。
- `norm.verified` 只有在 verified-rules.md 内或已联网核对官方原文时才为 `true`。
- 不要在任何字段里写还原后的单位、人员、工程名称。

## verify 后新增的字段

`located`（all / partial / none）、`quotes[].blocks`（文件、页码、页面坐标）、`verify_notes`、`merged_ids`、`scope: out_of_scope`。不要手工修改 `verified.json`。

## 报告结构（report 命令生成）

1. 审查概况：文件代号、格式、页数、已审查/未审查页数、SHA-256、审查重点、执行的检查项、结果计数、脱敏统计。
2. 疑似问题：汇总表 + 每条详情（结论、问题、原文引文与定位、判断依据、规范、缺少的条件、建议核对、人工处理勾选栏）。
3. 需补充条件。
4. 待查线索。
5. 核查范围与限制：未审查页（合并为页码区间）、文字偏少页、外部参照、未执行的检查项、固定限制声明。
6. 检查项与版本、核验统计。
7. 人工复核记录表（空白，由设计人员填写）。

报告首行固定声明：AI 辅助自查候选，须设计人员逐条确认，不是正式审图意见或合规结论。不要删除这句话，也不要在报告任何位置写“审查合格”“符合规范”。

坐标说明：页面点（1/72 英寸），左上角为原点 [x0, y0, x1, y1]；用 pypdf 抽取时为近似范围。
